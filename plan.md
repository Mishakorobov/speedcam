**Дата:** 22 октября 2026  
**Версия документа:** 2.0 (План исправления багов по результатам ручного тестирования)  
**Статус:** Утверждено к реализации

**Корень проекта:** `d:\contracam\speedcam\`

## 1. Контекст и анализ результатов ручного тестирования

В ходе натурного и ручного тестирования приложения на физическом устройстве были выявлены критические проблемы функциональности базы данных, работы сенсоров GPS, отображения карты, производительности UI-компонентов Jetpack Compose и локализации:

1. **Недоступность репозитория обновлений базы данных:**  
   По умолчанию URL манифеста базы указывает на еще неопубликованный удаленный репозиторий GitHub (`https://raw.githubusercontent.com/mishakorobov1950/speedcam/main/data/manifest.json`), из-за чего при проверке обновлений возникает ошибка сети / HTTP 404. Отсутствует возможность локального обновления из файла, сброса к встроенной базе и переключения на альтернативные зеркала.
2. **Баг 1 (Спидометр / GPS):** На стоянке спидометр показывает `1 км/ч`, а в начале движения скачет `0 → 1 → 2 км/ч`.
3. **Баг 2 (Карта):** Экран карты не загружается, не отображает дорожную сеть и остается невидимым/пустым.
4. **Баг 3 (Настройки / Слайдер):** Ползунок дистанции предупреждения тормозит, зависает и не реагирует на нажатия сразу.
5. **Баг 4 (База ContraCam):** При активации тумблера «Использовать ContraCam database» количество камер на карте не увеличивается (или сбрасывается в 0).
6. **Баг 5 (UX / Навигация):** Вкладка «Камеры» представляет собой плоский список из 80 000 точек, не несущий практической ценности для водителя.
7. **Баг 6 (Локализация):** Интерфейс приложения полностью на английском языке, требуется 100% перевод на русский язык.
8. **Баг 7 (Интерактивность настроек):** Кнопки, переключатели и чипы в настройках срабатывают не с первого раза.

## 2. Первопричины ошибок (Root Cause Analysis)

### 2.1 Обновление базы данных (GitHub недоступен)
* **Причина:** Жестко закодированный URL `DEFAULT_MANIFEST_URL` в `DatabaseSyncEngine.kt` ведет на закрытый/несуществующий репозиторий. Механизм обновления падает с исключением без возможности выбора файла из памяти устройства (`.db`/`.json`), без зеркала и без кнопки «Восстановить встроенную базу камер».
* **Решение:** 
  1. Реализовать импорт базы камер из локального файла через Storage Access Framework (SAF).
  2. Добавить кнопку ручного восстановления/переустановки базы из встроенных assets (`assets/databases/cameras.db`).
  3. Добавить поддержку кастомного URL зеркала и понятные русскоязычные сообщения об ошибках вместо сетевых стек-трейсов.

### 2.2 Баг 1: Джиттер скорости на месте (1 км/ч, разгон 0-1-2)
* **Причина:** GPS-чипсет смартфона в покое генерирует паразитный шум доплеровского сдвига и фазы несущей ($v \approx 0.15\text{--}0.35$ м/с). В `LocationSource.toFix()` значение скорости берется напрямую из `Location.getSpeed()`. При пересчете $0.3 \times 3.6 = 1.08$ км/ч функция `roundToInt()` в спидометре округляет его до **1 км/ч** на стоящем автомобиле. При трогании отсутствие низкоскоростного фильтра приводит к рывкам `0 → 1 → 2`.
* **Решение:** 
  1. Ввести порог покоя (deadband): при скорости $< 2.0$ км/ч ($0.55$ м/с) скорость принудительно обнуляется (`0.0 км/ч`).
  2. Добавить экспоненциальное сглаживание (EMA-фильтр) для плавного нарастания показаний спидометра при начале движения.

### 2.3 Баг 2: Карта не прогружается и не видна
* **Причина:** 
  1. `VectorRoadRepository` пытается загружать геометрию дорог на лету через неблокирующий HTTP-запрос к Overpass API (`overpass-api.de/api/interpreter`), который блокируется при плохом мобильном интернете или возвращает тайм-аут (5 сек).
  2. Порог `MIN_ROAD_ZOOM = 13.0f` отключает отрисовку дорог на средних зумах.
  3. Начальные координаты жестко зашиты в Москву (`55.7558, 37.6173`), и пока нет GPS-фикса, пользователь видит пустую сетку без дорог.
  4. На Canvas отсутствует базовая подложка тайлов (нет видимого контекста карты, городов, рек, трасс).
* **Решение:**
  1. Интегрировать надежный тайловый кэширующий слой (растровые/векторные тайлы OpenStreetMap / Carto Dark Matter с дисковым кэшем) либо гарантированный оффлайн-рендерер сетки дорог.
  2. Автоматически центрировать карту на последнюю известную позицию пользователя (`getLastKnownLocation`) или на ближайшие камеры из базы.
  3. Добавить индикатор загрузки и автономную fallback-сетку ориентиров.

### 2.4 Баг 3: Ползунок дистанции предупреждения лагает
* **Причина:** 
  1. `SettingsSliderItem` передает `value = state.captureDistanceKm`, однако `captureDistanceKm` в `MainActivity` читается напрямую из `ProfileStore` (`SharedPreferences`), а не из реактивного Compose `State` / `StateFlow`.
  2. При каждом микро-смещении ползунка `onValueChange` синхронно пишет в `SharedPreferences` на главном потоке.
  3. Из-за отсутствия локального состояния ползунок «залипает» до тех пор, пока внешний поток не вызовет рекомпозицию.
* **Решение:**
  1. Добавить локальное состояние `remember(item.value) { mutableFloatStateOf(item.value) }` внутри `SettingsSliderItem`.
  2. Передавать изменения во внешнее хранилище по событию `onValueChangeFinished` (или с дебаунсингом).
  3. Подключить реактивный `mutableDoubleStateOf` в `MainActivity`.

### 2.5 Баг 4: Тумблер ContraCam не увеличивает количество камер
* **Причина:** 
  1. Запрос `Daos.kt` при `useContraCam = 1` фильтрует `WHERE source = 3`. Если бинарный архив ContraCam еще не скачан, в таблице находится 0 записей с `source = 3`.
  2. Включение тумблера `useContraCamDb = true` в `MainActivity.onUseContraCamDbChange` не инициирует загрузку архива, а лишь переключает фильтр на пустой источник.
* **Решение:**
  1. При активации тумблера проверять наличие камер ContraCam (`countBySource(3)`). Если записей 0 — автоматически запускать загрузку и импорт архива с показом прогресса.
  2. Реализовать гибридный fallback: если база ContraCam пуста или загружается, продолжать отображать базовые камеры OSM/SpeedCam с уведомлением о синхронизации.
  3. Добавить отображение реального прироста камер на карте.

### 2.6 Баг 5: Бесполезность вкладки «Камеры»
* **Причина:** Список из 80 000 строк бесполезен водителю в движении и перегружает интерфейс.
* **Решение:**
  1. Устранить бесполезную отдельную вкладку «Камеры» из нижней панели навигации, сократив панель до трех понятных экранов: **Спидометр (Главная)**, **Карта**, **Настройки**.
  2. Полезный функционал (поиск объектов, фильтрация по типам, просмотр деталей и блокировка камер) перенести непосредственно на экран **Карты** в виде удобной выдвижной шторки (BottomSheet) «Камеры рядом» и «История предупреждений».

### 2.7 Баг 6: Полная русификация интерфейса
* **Причина:** Строки жестко закодированы на английском языке в коде Compose-экранов и сервисов.
* **Решение:**
  1. Сформировать полный русскоязычный ресурс `strings.xml` с автомобильной терминологией (Спидометр, Ограничение, Превышение, Камера контроля скорости, Контроль полосы, КСС, Радар-детектор, Часы Wear OS, Авто-запуск).
  2. Перевести все экраны (`MainActivity`, `StatusTab`, `VectorMapScreen`, `SettingsScreen`, `HudContent`, `PipContent`, `WearSpeedometerScreen`, `WearSettingsScreen`).

### 2.8 Баг 7: Кнопки в настройках нажимаются не с первого раза
* **Причина:**
  1. В `SettingsToggleItem` кликабелен только миниатюрный переключатель `Switch`. Клик по строке, названию или описанию игнорируется.
  2. Использование горизонтального `LazyRow` внутри вертикального `verticalScroll(rememberScrollState())` вызывает конфликт жестов: малейшее диагональное движение пальца перехватывается скроллом, срывая клик.
  3. Прямые синхронные вызовы `ProfileStore` блокируют UI-поток.
* **Решение:**
  1. Сделать всю строку настройки интерактивной через `Modifier.toggleable(value = checked, onValueChange = onCheckedChange, role = Role.Switch)`.
  2. Заменить `LazyRow` в селекторах (транспорт, каналы звука, задержка Bluetooth) на `FlowRow` или адаптивную сетку без конфликтующих вложенных скроллов.
  3. Обеспечить минимальный размер области нажатия 48x48 dp (WCAG Touch Target).
